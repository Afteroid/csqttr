**CSQTT** — Android-приложение и высокопроизводительный сервер для создания защищённого туннеля поверх TURN/RTP. Клиент поднимает локальный интерфейс на устройстве, маскируя транспорт под зашифрованный медиатрафик звонка.

**Кросс., проекты с поддержкой CSQTT**: 
- Windows & Linux порт - [luminescq/focsq](https://github.com/luminescq/focsq)
- ios совместимый клиент - [anton48/vk-turn-proxy-ios](https://github.com/anton48/vk-turn-proxy-ios)

**Прекрасный аналог csqtt / wdtt**: [hackdiaz-dev/turn-proxy-android](https://github.com/hackdiaz-dev/turn-proxy-android)

## SSH-порт при деплое

В параметрах сервера укажите фактический порт SSH на VPS (по умолчанию — 22).
SSH-порт расположен рядом с IP сервера. PEER и WEB редактируются напрямую;
переключателя «Ручные порты» в новой форме деплоя нет.

Если ранее введённый SSH-порт сбросился на 22, введите его заново и сохраните
параметры сервера. Отказ соединения на SSH-порту возникает до проверки пароля;
работающее подключение VLESS не подтверждает доступность SSH.

На этапе установления SSH-соединения используются тайм-ауты 15 секунд.
При сетевом тайм-ауте клиент закрывает сокет и один раз повторяет подключение;
этот повтор выполняется до аутентификации и запуска любых команд на VPS.
Ошибки ключа сервера и аутентификации автоматически не повторяются.

Для отдельной тестовой установки, сохраняющей установленную debug-версию,
соберите `assembleDebug -Pcsqtt.abis=arm64-v8a -Pcsqtt.debugApplicationIdSuffix=.sshfix -Pcsqtt.debugAppLabel="CSQTTR SSH Fix"`.
Пакет будет называться `csqtt.quic.amurcanov.sshfix`; без этого параметра
debug-сборка сохраняет прежний суффикс `.forktest`.

## Новый интерфейс и сборка для ревью

Новый интерфейс реализован на Android Compose: подключение со списком серверов
и проверкой трафика через туннель, отдельная вкладка «Туннель», компактная форма деплоя и настройки.
По умолчанию выбран участник. Режим владельца в шестерёнке открывает деплой,
не меняя данные и способ авторизации профиля VPN.

Выбор VPS сохраняется отдельно от выбранного профиля подключения. После успешной
установки сервер получает связанный профиль с адресом, PEER-портом и паролем.
Ошибка деплоя не заменяет пароль подключения.

«Пинг» последовательно запускает отдельный процесс ядра для каждого профиля:
VK/TURN, аутентификация CSQTT, получение TUNCONF и DNS-запрос `example.com`
через выданный ядру виртуальный TUN. Показанное время — задержка этого DNS-обмена
внутри туннеля, без времени авторизации. Прямого ICMP/TCP/HTTP fallback нет.
Тест использует одну группу из 10 потоков и один хеш; авто API создаёт собственный временный звонок.
Системный VPN-интерфейс и выбранный профиль не меняются. Проверка доступна при
отключённых VPN, отменяется кнопкой и закрывает процесс/свой звонок при выходе.
Наличие TUNCONF без ответного пакета не считается успешной проверкой.
При необходимости интерактивной капчи сначала подключитесь обычным способом.

Вход VK сразу открывает веб-страницу для телефона/почты и пароля.
Отдельного выбора или кнопки входа через приложение VK нет.
Сохраняется существующий OAuth client ID проекта.
При выборе импортированного профиля во вкладке «Туннель» используются его адрес,
PEER-порт, пароль, хеши либо VK-токен. Настройки других профилей не перезаписываются.
Потоки выбираются с шагом 10, минимум 10; сохранение и запуск применяют общую
политику `WorkerCountPolicy`. Окно ручных хешей содержит шесть компактных полей.

Пример отдельной debug-сборки, которая не заменяет прежние `.forktest` и `.sshfix`:

```text
gradlew.bat :app:assembleDebug -Pcsqtt.abis=arm64-v8a -Pcsqtt.debugApplicationIdSuffix=.happdebug -Pcsqtt.debugAppLabel=csqtt_debug -Pcsqtt.debugVersionNameSuffix=-debug.5
```

Имя под иконкой — `csqtt_debug`, пакет — `csqtt.quic.amurcanov.happdebug`.
Это стандартная подпись Android debug, не ключ автора исходного APK.
Интерфейс показывает только основную версию, без служебного суффикса сборки.
Подсказки режимов разбиты на разделы, пустые поля показывают формат ввода.
В логах доступны фильтры уровня и источника; ошибки выделяются красным, успешные
и сетевые сообщения — зелёным. Декоративные разделители сообщений скрыты.
Данные VPS записываются одной операцией с явным номером профиля: адрес, SSH-доступ,
порты, настройки панели и службы. Потоки эта операция не меняет. SSH-ключи и их
пароли также сохраняются для конкретного VPS. Сохранение нового VPS создаёт в том же
связанный профиль подключения с названием, адресом, PEER-портом и паролем туннеля;
если VPN остановлен, этот профиль выбирается в интерфейсе. Потоки не копируются.
До установки пароль нового профиля синхронизируется с формой VPS; у уже настроенного
сервера рабочий пароль меняется после успешной установки. Пароли туннеля и панели
генерируются заранее для нового VPS, логин панели по умолчанию — `admin`.
Сохранённые пароли не генерируются повторно. SSH-пароль пользователь вводит сам.
Личный VK-аккаунт используется всеми профилями. Токен из импортированной ссылки
остаётся локальным переопределением своего профиля и не становится общим аккаунтом.
Последние режимы хешей и авторизации, SRTP, транспорт, TURN-подсеть и число потоков
хранятся отдельно для каждого профиля. «Экстра потоки» сохраняются между запусками.
Перед запуском установки все данные VPS сохраняются независимо от дальнейшего
результата SSH/установки. Повторная попытка использует ту же связь с подключением.
Удаление подключения отменяет старые черновики этого слота: отложенные записи
туннеля и автосохранение VPS не создают его снова. Явное добавление нового VPS или
новая попытка установки могут восстановить подключение.
Если уже есть единственный профиль с тем же адресом и PEER-портом, используется он,
без создания копии. Пустой пароль заполняется; существующий пароль подключения
сохраняется до успешной установки, а новые реквизиты остаются в форме VPS.
В деплое можно добавить несколько VPS кнопкой «+» и переключаться нажатием на название.
Карандаш рядом с названием открывает редактирование выбранного VPS. Черновики при
возврате на вкладку загружаются из сохранённого слота, без восстановления чужой формы.
Результаты пинга профилей и TURN сохраняются при переходах между вкладками и закрытии
диалога в пределах текущего сеанса приложения. Новый замер обновляет соответствующий
результат. Кнопка «Пинг» не меняет название; остановка вынесена в отдельный крестик.
Реквизиты веб-панели и генератор пароля туннеля находятся в основной форме; кнопки
установки и удаления закреплены внизу. Корзина удаляет данные управления VPS из
приложения, сохраняя связанный профиль подключения. Удаление серверной части —
отдельное подтверждаемое действие. Режим приложения выбирается кнопками
«Участник / Владелец». Светлая тема использует синюю кнопку подключения и голубые
дорожки переключателей; тёмная — контрастные дорожки и небольшой бегунок.
Путь к установленному SDK укажите в собственном `local.properties` (`sdk.dir=...`);
локальные настройки, APK, ключи подписи и каталоги сборки в Git не включаются.
Для сборки используются JDK 21, Android SDK 37 и Gradle Wrapper из репозитория.
Старые Android Studio могут не поддерживать AGP 9.2 из проекта; сборка через
Wrapper от IDE не зависит.

Нативные клиентские библиотеки и серверные исполняемые файлы подготавливаются
отдельно через `rust-client/build_so.bat`, сборку `rust-server` и скрипты
из `scripts/`. Пересборка Android-интерфейса сама по себе не пересобирает Rust.

Инструментальные тесты `HappInterfaceTest` проверяют навигацию, режим владельца,
доступность полей и независимость данных VPS/профиля на эмуляторе.
Они не запускают VPN, SSH и деплой на настоящем сервере.

В настройках доступен «Дизайн»: текущий «Новый» (по умолчанию) и «Классический».
Выбор общий для приложения, настройки подключения не копируются между дизайнами.
Нижние вкладки нового дизайна переключаются сразу; состояние деплоя загружается
заранее. Переключатели анимируются только от нажатия, сохранённые значения появляются
без повторного движения. Неизменённые секреты не шифруются и не записываются заново.

«Экономия батареи» совместима с принятой реализацией из [PR #15](https://github.com/Afteroid/csqttr/pull/15):
«Авто» следует энергосбережению Android, «Свой уровень» работает при выбранном заряде
и ниже без зарядного устройства, «Выкл» сохраняет обычную блокировку процессора.
Wi-Fi-блокировка остаётся; установка защищена от отпускания CPU-блокировки.
При экономии с выключенным экраном VPN может засыпать, задерживая трафик и уведомления.
Это изменение клиента: сервер и протокол не меняются, редеплой для него не требуется.
Интегрированы изменения upstream из PR #13–16: проверки сервера и смены SSH-ключа,
выбор дизайна, экономия батареи и хеши участников. Импорт ссылки с хешами сохраняет
адрес, порт и пароль в полях профиля, а хеши владельца — отдельно от собственных.
В обоих дизайнах участник видит количество и состояние хешей владельца, может убрать
их или вернуть и добавить свои. Значения хешей владельца в диалогах и логах скрыты.

В режиме участника «Показывать вкладку «Логи»» управляет видимостью вкладки отдельно
от записи событий. Выбор сохраняется для текущего профиля и применяется в обоих
дизайнах; у владельца вкладка доступна постоянно. В новом интерфейсе доступны
настройки капчи (авто, WBV/RJS, ручной/автоматический обход), управление VK-сессией,
все пять TLS-отпечатков, монитор ресурсов и информация об обновлениях. Дополнительные
действия веб-панели открываются кнопкой с тремя точками на вкладке деплоя. Смена пути
требует отдельного подтверждения и выполняет существующую серверную операцию.
Кнопка настроек капчи находится сразу под режимом кредов. Основная форма туннеля
проверена без прокрутки на портретном экране 360×720 dp в светлой и тёмной темах;
при открытой клавиатуре или увеличенном системном шрифте прокрутка остаётся доступной.
