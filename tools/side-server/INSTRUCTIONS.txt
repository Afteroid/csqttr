Параллельный сервер CSQTT (отдельно от Android-приложения)

deploy-side.sh — самостоятельная копия установщика с сохранёнными исправлениями
изоляции второго экземпляра. Она принудительно работает только в режиме side;
CSQTT_INSTANCE=main отклоняется. В csqtt_debug эти изменения не добавляются.
Экспериментальные изменения upload, диагностики и расхода батареи сюда не входят.

Исходники ядра: rust-server/ в этом репозитории. Поддержка --instance, --iface,
--tun-addr и --no-nat уже есть в базовом ядре. Сборка штатным
rust-server/build_linux_variants.ps1; готовые экспериментальные бинарники
CSQTT Test не использовать. Выберите бинарник под архитектуру сервера.

Разделение экземпляров:
  основной: csqtt.service, /etc/csqtt, интерфейс csqtt1
  второй:   csqtt25.service, /etc/csqtt25, /usr/local/lib/csqtt25/csqtt25
            интерфейс csqtt25, сеть 10.66.68.0/24
            UDP 46100, HTTPS 46102
  второй запускается с --instance csqtt25 --iface csqtt25
    --tun-addr 10.66.68.1/24 --no-nat
  установщик создаёт собственные правила CSQTT25_MANAGED / CSQTT25_TPROXY.

Условия: Linux с systemd, root, работающий IPv4 forwarding, свободные порты
и подсеть. Второй экземпляр не перенастраивает общие sysctl, маршрут шлюза
или WAN-интерфейс. Проверки установщика отклоняют конфликтующие порты и
несовместимое ядро. Это два сервера в одном сетевом пространстве, не полная
изоляция контейнеров/сетевых пространств. Нельзя параллельно запускать два
деплоя: временные upload-файлы общие со штатным установщиком.

Первичная установка (команды выполняются НА СЕРВЕРЕ):
1. Загрузить deploy-side.sh и штатный серверный бинарник.
2. Поместить бинарник в /tmp/.csqtt-upload-server (chmod 700).
3. С umask 077 создать /tmp/.csqtt-upload-web.env:
     CSQTT_WEB_USER=your_user
     CSQTT_WEB_PASS=your_unique_password
     CSQTT_WEB_SECRET_PATH=your_unique_random_path
   Значения — собственные, не переносить пароли основного экземпляра.
4. С теми же правами создать /tmp/.csqtt-upload-overrides.json:
     {"main_password":"your_unique_tunnel_password"}
5. Запустить (SSH_PORT — фактический порт SSH):
     CSQTT_SSH_PORT=5052 bash deploy-side.sh install
   Необязательные переменные: CSQTT_PEER_PORT, CSQTT_WEB_PORT.
   Установка использует штатный механизм сертификатов Let's Encrypt;
   для его проверки доступности нужен порт 80. Не копировать тестовые ключи.
6. Проверить:
     systemctl status csqtt25.service
     journalctl -u csqtt25.service -n 50 --no-pager
     bash deploy-side.sh status
   В профиле клиента указать адрес сервера и UDP-порт 46100, свой пароль.

Обновление: загрузить новый штатный бинарник в /tmp/.csqtt-upload-server,
затем CSQTT_SSH_PORT=5052 bash deploy-side.sh update.
Настройки и база второго экземпляра сохраняются. Для нестандартных портов
повторять их значения через переменные при каждой операции.

Удаление только второго экземпляра:
  bash deploy-side.sh uninstall  — оставляет /etc/csqtt25 с данными.
  bash deploy-side.sh purge      — удаляет также его базу и сертификаты.
Не подменять deploy-side.sh штатным deploy.sh: у штатного режим по умолчанию main.

Перед операцией и после неё сверять PID основного csqtt.service и хеши его
бинарника, unit-файла и конфигурации. Удаление csqtt25 проверено на тестовом
сервере: основной процесс продолжил работать с прежним PID и файлами.
Новая установка этой отдельной копией после очистки не выполнялась.
