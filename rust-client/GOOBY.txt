Подключение CSQTTR rust-client через Gooby

Назначение
Необязательная обработка Gooby для существующего транспорта TURN TCP/TLS.
В csqtt_debug: вкладка «Туннель», транспорт TCP/TLS, переключатель Gooby.
По умолчанию выключен; значение хранится отдельно для каждого профиля.
При UDP значение сохраняется, но Gooby не запускается. При удалении профиля
значение сбрасывается. Импорт старого JSON без этого поля оставляет Gooby выключенным.
APK содержит Gooby как библиотеку Rust-ядра: отдельный запуск/приложение не нужны.
При включении ядро создаёт внутренний listener на свободном loopback-порту;
при отключении/ошибке/завершении ядра listener и соединения уничтожаются.
Постоянного фонового сканирования или таймера Gooby вне туннеля нет.
На VPS ничего устанавливать не нужно.
Совместимость проверяется с интерфейсом https://github.com/Endlad2/Gooby:
SOCKS5 CONNECT, no-auth, адрес назначения IPv4/IPv6 либо DNS-имя.
Проверенная ревизия Gooby: c85b1a9744162bdafb8b6f1572fbb8c035ca605f.

Использование
Встроенный режим Rust CLI:
   --turn-transport tcp --gooby
Встроенная конфигурация TURN обрабатывает первые два Allocate запроса на TCP
(включая IP-назначения), либо ClientHello на настоящем TLS endpoint.
Выбор: --gooby-strategy current|gentle|extended; без параметра — current.
current: границы TURN 1/6/8/20, пауза 5 мс; TLS SNI частями по 2 байта, 10 мс.
gentle: границы TURN 6/20, пауза 1 мс; TLS SNI по 8 байт, 1 мс, без low-TTL.
extended: границы TURN 1/2/5/7/8/20, пауза 10 мс; TLS SNI по 1 байту, 15 мс.
current и extended сохраняют существующий low-TTL шаг для TLS, если он разрешён.
Для отключения low-TTL при диагностике: --gooby-no-disorder.
Установившийся поток данных не получает дополнительных задержек.
Расширенная стратегия экспериментальная: гарантии обхода или скорости нет.

Android: «Туннель» → TCP/TLS → Gooby → «Стратегия Gooby».
Выбор хранится в профиле и применяется при следующем подключении.
Старые профили и неизвестное значение используют current. UDP выбор игнорирует.
Лог «Выбрана стратегия» показывает конфигурацию; «Применено» — событие обработки.
Опционально можно передать ZIP правил: --gooby-config /path/rules.zip;
он несовместим с --gooby-strategy и сохраняет прежнее поведение пользовательских правил.

Внешний Gooby для разработчиков (прежний вариант сохранён):
1. Запустить Gooby со своей конфигурацией правил для используемого TURN:
   gooby turn-config.zip --listen 127.0.0.1:1080
2. К существующей команде rust-client добавить:
   --turn-transport tcp --gooby-proxy 127.0.0.1:1080
   Остальные параметры, CSQTT_PASSWORD, VK-авторизация и адрес peer прежние.
   Не заменять --turn, --peer или клиентский --listen адресом Gooby.

Также поддерживается локальный IPv6 listener: --gooby-proxy [::1]:1080.
Принимается только числовой loopback IP с ненулевым портом, без socks5://.
Одинарный дефис -gooby-proxy поддержан наравне со старыми CLI-параметрами.
--gooby-proxy и --gooby взаимно исключаются. Без обоих параметров Gooby не работает.

Совместимость и маршрутизация
Без --gooby и --gooby-proxy используются прежние прямые подключения TCP/TLS и UDP.
Сочетание любого варианта Gooby с UDP отклоняется с явной ошибкой до подключения.
При ошибке прокси нет скрытого перехода на прямой TCP или UDP.
Прокси используется только для TURN TCP/TLS; VK HTTPS и прямые исключения
маршрутизации не перенаправляются автоматически через него.
Каждый TURN stream проходит SOCKS5-согласование; повторное подключение также
использует тот же прокси. Ожидание соединения и SOCKS5 ограничено тайм-аутом.
Исходное имя назначения передаётся Gooby без локального разрешения DNS.
Ручной override адреса TURN по-прежнему учитывается. Если это IP, Gooby
получит IP: встроенная TURN-стратегия обрабатывает Allocate и для IP.
Профили, подписки, пароль, TURN-авторизация, SRTP/DTLS/WRAP и серверный
формат сообщений не меняются. iOS C ABI не меняется; прокси там выключен.

TLS и эффективность обхода
Пункт TCP/TLS не принуждает TLS: turn: использует TCP, turns: использует TLS.
Gooby не превращает обычный TURN TCP в TLS. Для base с дроблением ClientHello
нужен настоящий TLS endpoint, поддерживаемый провайдером TURN.
TLS handshake выполняется после SOCKS5 CONNECT. Сертификат и имя проверяются
относительно исходного TURN, а не localhost. Отключения проверки нет.
Пример gooby-youtube.zip не содержит правил TURN и сам по себе не включает
обработку нужных TURN-доменов. Конфигурация должна соответствовать назначению.
Произвольная Lua-трансформация, меняющая полезные данные, может нарушить TURN;
этот адаптер не добавляет обратное преобразование на сервере.
Во встроенной версии ограничены ожидания и число соединений; ошибка
восстановления TTL закрывает соединение. Поддержка пользовательских Lua ZIP
предназначена для доверенных конфигураций; их совместимость с конкретным
протоколом нужно проверять отдельно.
Поддержка SOCKS5 не является доказательством улучшения скорости или обхода DPI.
Это требуется измерить отдельно в проблемной сети.

Android и игры
Gooby работает внутри процесса ядра под UID приложения. TunVpnService уже
исключает этот UID из VPN; во включающем списке он также не добавляется.
Не следует менять это исключение при дальнейшем переносе Gooby.
UDP-транспорт CSQTT не изменён. Перед выпуском TCP как запасного варианта
следует проверить задержки и потери в играх; ускорение/совместимость Steam
не подтверждается только локальными тестами SOCKS5.

Локальная проверка
Из rust-client:
   cargo test --locked gooby
   cargo test --locked turn::
   cargo test --locked turn_stream::
Тесты используют локальные заглушки SOCKS5/TURN/TLS, включая аутентификацию
TURN, ChannelBind, передачу данных, deallocation, проверку сертификата,
тайм-ауты, отмену и отсутствие прямого fallback. Они не обращаются к VPS/ВК.
Встроенный движок также проверяется с base и включённым low-TTL на loopback:
передача TURN поверх TLS, сохранение SNI, закрытие listener и соединений.
Android smoke-пример: cargo ndk -t x86_64 -P 26 --link-builtins build --release --example gooby_smoke.
Он принимает необязательный ZIP правил и проверяет локальную передачу данных
и завершение движка; не устанавливает VPN и не обращается к серверам.

Сборка APK-ядра в Linux/WSL с Linux Android NDK:
   ANDROID_NDK_HOME=/path/android-ndk bash rust-client/build_android_wsl.sh arm64-v8a x86_64
После сборки в PowerShell обновить и проверить provenance для выбранных ABI:
   ./scripts/native_client_provenance.ps1 -Mode Write -Abis @('arm64-v8a','x86_64') -Producer rust-client/build_android_wsl.sh
   ./scripts/native_client_provenance.ps1 -Mode Verify -Abis @('arm64-v8a','x86_64')
В csqtt.abis указывать только реально пересобранные архитектуры.

Есть отдельная явно запускаемая проверка с настоящим процессом Gooby:
   cargo test --locked real_gooby_base_tls -- --ignored --nocapture
Для неё задать GOOBY_TEST_BIN (абсолютный путь к исполняемому Gooby) и
GOOBY_TEST_CONFIG (абсолютный путь к ZIP с rules.db). Тестовая rules.db:
   CREATE TABLE rules(domains TEXT NOT NULL, strategy TEXT NOT NULL, script TEXT);
   INSERT INTO rules VALUES ('["localhost"]', 'base', NULL);
rules.db должна лежать в корне ZIP, скрипты для base не требуются.
Тест сам запускает и останавливает Gooby на свободном loopback-порту,
создаёт локальный TLS endpoint и проверяет SNI/передачу TURN ChannelData.
Gooby запускается с --no-disorder: проверяется совместимость дробления TLS,
а не действие низкого TTL на реальном маршруте или скорость обхода DPI.
